# PushPlus 内嵌用量图表设计

## 目标

彻底消除 PushPlus 消息对外部图片地址的依赖。新广播继续展示三项 Go 额度、最近 24 小时请求数、Token 分类、费用和模型排行，并在消息正文中直接加入最近 24 小时的逐小时条形图。

自动广播仍为北京时间 09:00 至 23:00 每小时一次，00:00 至 08:59 不发送；手动触发、幂等、outbox 重试和采集规则保持不变。

## 根因与方案选择

PushPlus 开放接口实测稳定返回 `403：IP未授权`。其官方接口要求获取 AccessKey 的服务器位于安全 IP 白名单内，而普通 Cloudflare Worker 没有固定出口 IP。因此，Worker 直接上传 PushPlus 官方图床无法长期运行。

本次采用纯正文图表：每个小时显示北京时间、按该小时总 Token 归一化后的条形条和精确 Token 数值。条形条由普通 Unicode 方块组成，不使用 `<img>`、SVG、Canvas、远程字体、CSS 背景或任何网络资源。即使客户端简化 HTML 样式，时间、方块和数值仍能作为普通文字显示。

不采用以下方案：

- 固定 IP 中控：需要新增长期运行的服务器和运维。
- 七牛云等国内图床：需要新增供应商账号、实名和凭据。
- R2、`workers.dev` PNG 或其他境外图床：仍无法消除中国大陆微信访问跨境资源的可靠性问题。

## 消息展示

最近 24 小时图表固定包含 24 行，顺序与现有聚合桶一致。每行格式为：

```text
09时 ███████░░░ 123,456 Token
```

规则如下：

- 时间使用 `Asia/Shanghai` 和 24 小时制。
- 每行时间取该聚合桶的开始时间；每小时总量为输入、输出、推理和缓存 Token 之和。
- 以 24 个小时中的最大值作为十格条形条的满格；非零小时的实心格数为 `ceil(该小时总量 / 最大值 × 10)`，其余位置用 `░` 补足十格；零值显示十个 `░`。
- 数值继续使用中文千分位格式，图表之外的 Token 分类汇总保持不变。
- 聚合结果被截断时，保留现有“仅含已采集记录”提示。
- 聚合不可用时，不显示伪造图表，继续使用现有不可用原因文案。

## 代码边界

- `src/rules.ts` 新增一个只接收 `UsageAggregate` 的内嵌图表渲染函数，由 `renderUsageDetails` 调用。
- `UsageDetailsView` 不再需要 `chartUrl`。可用聚合一经取得即可生成完整消息，无额外网络阶段。
- `src/app.ts` 删除新广播中的 Browser Run 和 PushPlus 图片上传调用；事件仍只提交一次并沿用现有 outbox 投递。
- 删除不再使用的 PNG 截图和 PushPlus 图片上传生产模块、相应测试、`BROWSER` binding 与 `PUSHPLUS_SECRET_KEY` 必填配置。
- 保留历史 `/charts/usage/*.svg` 路由、签名 Secret、D1 快照表及 30 天清理逻辑，让已经发送的旧消息继续工作。

## 失败与安全

内嵌图表是确定性的同步字符串渲染，没有外部超时、鉴权、上传或图片加载失败路径。所有动态文字仍经过现有 HTML 转义；图表新增内容只由受验证的时间戳和非负整数生成。

上线后关闭本次临时启用的 PushPlus 开放接口，并删除 Cloudflare 中不再使用的 `PUSHPLUS_SECRET_KEY`。不在日志、仓库、消息或 PR 中记录任何 Token、SecretKey 或 AccessKey。

## 精简测试

- 规则层：覆盖有用量、全零、极端比例、北京时间标签和截断提示，断言正文中不存在 `<img>`。
- 应用层：覆盖可用聚合直接生成内嵌图表、聚合不可用继续降级、重复触发不重复创建事件。
- 回归：现有额度、24 小时聚合、定时窗口、手动触发、outbox 和历史 SVG 路由测试继续通过。

## 上线与验收

1. 合并后部署 Worker，确认生产版本不再要求 `BROWSER` 或 `PUSHPLUS_SECRET_KEY`。
2. 只触发一次手动广播。
3. 在 PushPlus 消息详情和微信中确认：三项额度与明细完整；24 行条形图和精确数值可读；正文没有外部图片请求。
4. 关闭 PushPlus 开放接口并删除无用 Cloudflare Secret。

验收标准是新消息无需刷新图片即可完整显示图表，同时原有发送时间、手动触发、幂等和历史消息兼容行为不变。
