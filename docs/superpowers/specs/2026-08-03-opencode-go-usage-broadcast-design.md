# OpenCode Go 配额自动广播设计

- 日期：2026-08-03
- 状态：设计已确认，等待用户审阅书面规格
- 部署目标：Cloudflare Workers、D1、PushPlus

## 1. 决策摘要

系统每 30 分钟读取一次 OpenCode Go 控制台展示的三档官方配额：5 小时、每周和每月使用百分比及重置时间。系统只在跨越 50%、75%、90% 或 100% 阈值时创建提醒，并在每天北京时间 09:07 创建一个完整汇总逻辑事件。

采集任务运行在 Cloudflare Workers，无需任何人的电脑常开。D1 保存去重和故障状态。PushPlus 私有群组把同一条消息分别推送到 2–5 位成员的微信服务号会话。

OpenCode Go 当前没有正式的配额查询 API。生产环境启用控制台采集器前，账号持有人必须取得 OpenCode 对自动读取控制台的书面许可。采集层必须保持可替换，以便官方 API 上线后直接迁移。

## 2. 目标与非目标

### 目标

- 广播 OpenCode Go 的 5 小时、每周、每月使用百分比和重置时间。
- 每 30 分钟检查一次，但仅在需要时发送消息。
- 在 50%、75%、90%、100% 阈值以及每日汇总时间发送通知。
- 支持 2–5 位成员自行扫码订阅和退出。
- 无需常开电脑或自建服务器。
- 不保存 GitHub 密码，不自动模拟 GitHub 登录。
- 登录失效、上游故障或页面改版时安全暂停，不产生虚假数据。

### 非目标

- 不统计每位成员分别使用了多少 token。
- 不广播请求、会话、模型、项目、费用明细或提示词。
- 不提供公开仪表盘、成员后台或远程控制界面。
- 不通过个人微信协议、桌面 Hook 或模拟个人微信账号发送消息。
- 不绕过 OpenCode、GitHub、Cloudflare 或 PushPlus 的访问控制和服务条款。

## 3. 外部约束与启用门槛

1. OpenCode Go 文档公开了模型调用端点，但截至 2026-08-03 没有正式的配额查询端点。
2. 拟议的 Go 用量端点仍是未合并的公开 PR。
3. OpenCode 现行条款限制自动化提取和页面抓取。
4. 因此，控制台采集适配器默认禁用。只有取得书面许可后才可配置生产凭据并启用。
5. 若未取得许可，可以完成调度、状态机、通知和模拟测试，但不能在生产环境自动读取控制台。

生产配置中的 `OPENCODE_CONSOLE_ENABLED` 默认固定为 `false`，同时作为紧急停用开关。书面许可由账号持有人在系统外留档，至少记录：有权授权的主体、账号与工作区、允许访问的端点和数据字段、访问频率、Cloudflare 重放 OpenCode 会话 Cookie 的方式、PushPlus/微信接收人范围、生效和到期时间、撤销方式及复核人。

生产环境还必须配置非敏感的许可记录 ID 和到期时间。许可缺失、过期、被撤销、与当前账号或工作区不匹配，或采集开关不是 `true` 时，Worker 在发送任何带认证的 OpenCode 请求前失败关闭。这个技术开关只是防误启用措施，不代替许可本身。

## 4. 总体架构

数据流如下：

Cloudflare Cron → 用量源适配器 → 校验与标准化 → 阈值规则引擎 → D1 状态库 → PushPlus 私有群组 → 成员微信服务号会话

### 4.1 Cloudflare Worker

- 提供每 30 分钟的定时入口。
- 提供每天北京时间 09:07 的汇总入口。
- 串联采集、校验、规则判断、状态持久化和通知发送。
- 生产 Worker 只提供一个按事件做 HMAC 签名的 PushPlus 结果回调入口，不提供公开业务接口；未识别的 HTTP 请求返回 404。

### 4.2 用量源适配器

适配器只负责返回统一的配额快照，不负责通知或持久化。统一快照包含：

- 来源类型和抓取时间；
- 5 小时、每周、每月三个窗口；
- 每个窗口的已用百分比和重置时间；
- 数据是否完整、是否过期。

首个生产适配器是经授权的 OpenCode 控制台适配器。未来官方 API 可用时，用官方 API 适配器替换它，规则引擎、D1 和 PushPlus 均无需修改。

控制台适配器必须使用固定的 `GET` 方法、精确的 HTTPS origin、标准 443 端口和允许路径，并设置 `redirect: manual`。工作区 ID 只能作为经过编码的路径段或查询参数，不能影响 origin。Cookie 只在上述检查全部通过后附加到这一个请求；任何跳转、相似域名、用户信息 URL、非标准端口或非允许路径都失败关闭。

### 4.3 校验与标准化

- 三个窗口必须同时存在。
- 百分比必须是 0–100 的有限数值。
- 重置时间必须能解析为有效时间。
- 响应不得是登录页、错误页或跨域重定向结果。
- 任一关键字段缺失时整次快照无效，不能用 0 或旧字段补齐。

### 4.4 D1 状态库

D1 只保存非敏感状态：

- 每个调度任务的唯一键、类型、逻辑调度时间和观察开始时间；
- 每个窗口最近一次有效百分比、重置时间、周期键和单调观察版本；
- 每个窗口、周期和阈值的消费状态；
- 不可变的广播事件载荷、状态、尝试次数、租约、下次尝试和过期时间；
- 广播事件与一个或多个阈值触发项之间的成员关系；
- PushPlus 消息流水号、最终回调状态和每次尝试记录；
- 每日汇总最后成功发送的北京时间日期；
- 故障 episode、告警/恢复转换和连续失败的常规半小时槽位。

D1 不保存 Cookie、PushPlus Token、工作区原始页面、邮箱或 GitHub 信息。

阈值触发项使用“窗口 + 周期键 + 阈值”作为唯一键；每日汇总使用“北京时间日期 + 汇总类型”作为唯一键；故障转换使用“故障类别 + episode ID + 告警或恢复”作为唯一键。多个窗口同时触发时，系统创建一个确定性的广播事件，并把各触发项写入成员关系表；最终成功会同时完成全部成员项。

每个被接受的快照，无论来自常规入口还是每日汇总入口，都必须先经过同一个阈值状态转换，再推进最新基线。创建事件、消费阈值、更新窗口状态和写入成员关系必须在一个 D1 批处理事务中完成。旧观察晚于新观察完成时，其单调版本检查必须拒绝更新，不能回退快照或健康状态。只有不同的常规半小时调度槽位可以增加连续失败计数；每日任务失败不能加速“三周期失败”告警。

广播发送采用事务性 outbox。只有通过条件更新把 `pending/retryable` 原子变为带到期租约的 `sending`，且确认恰好修改一行的执行者，才有权调用 PushPlus。过期租约可由后续任务接管；初次发送和重试使用同一套抢占规则。

### 4.5 PushPlus

- 账号持有人创建私有普通群组并完成发送方实名认证。
- 2–5 位成员通过限时、限次数二维码订阅。
- Worker 使用一个发送 Token 和一个群组编码完成一对多推送。
- 每次请求携带指向 Worker 的专用结果回调 URL；URL 包含事件 ID、回调截止时间和由独立 Secret 生成的事件级 HMAC 签名，不直接包含 Secret。
- 消息仅包含配额、重置时间、更新时间和监控状态。
- 成员退出后由群组管理员复核并移除；群组二维码不公开发布。

## 5. 调度设计

Cloudflare Cron 使用 UTC：

- 常规检查："*/30 * * * *"。
- 每日汇总："7 1 * * *"，对应北京时间 09:07。

常规检查每天执行 48 次。检查不等于通知；数据未跨阈值时不发送消息。每日汇总入口也先把新快照送入统一阈值状态机，再单独创建汇总事件；例如 09:00 为 49%、09:07 为 76% 时，应产生一条 75% 阈值提醒和一条每日汇总，09:30 不得重复。

Cloudflare Cron 以 `controller.scheduledTime` 标识逻辑槽位，但平台可能延迟实际启动，因此 09:07 是逻辑计划时间而非秒级送达承诺。去重使用逻辑槽位，消息显示实际数据抓取时间；部署验收允许平台自身的调度延迟。

从每天 49 次计划执行和少量 D1 读写来看，预计可落在 Cloudflare 免费计划配额内。实现阶段仍必须实测解析所需 CPU 并复核部署时的最新限制；若超限，则改用付费 Worker，或退回小型 VPS 方案，不得通过删减数据校验来勉强运行。

## 6. 登录与凭据生命周期

OpenCode 使用 GitHub OAuth 完成首次身份确认，随后由 OpenCode 自己的 `auth` 会话 Cookie 访问控制台。当前 OpenCode 源码把该会话的最大年龄配置为 365 天，但这不是稳定的服务承诺，也不能作为安全控制依据；实际会话可能因退出登录、密钥轮换、安全策略或服务改版提前失效。

系统不保存 GitHub 用户名、密码、Passkey、两步验证码或 GitHub 浏览器 Cookie。初始流程为：

1. 账号持有人在自己的浏览器中正常使用 GitHub 登录 OpenCode。
2. 只提取 `auth` Cookie 的原始值，并作为高敏感凭据写入 Cloudflare Secrets；Cookie 名称由代码固定。
3. Worker 校验许可、开关、精确目标和 Cookie 格式后，构造唯一的 `auth=<原始值>` Cookie 对读取经授权的用量来源。
4. 收到 401、403、登录页或认证重定向时，把当前非敏感凭据代数记入 `AUTH_BLOCKED` 状态，并通过独立的 PushPlus 凭据创建一个会话失效逻辑事件。
5. 同一凭据代数处于 `AUTH_BLOCKED` 时，后续任务不得向 OpenCode 发请求。持有人重新登录、更新 Secret，并递增非敏感的 `OPENCODE_AUTH_GENERATION`。
6. 新代数通过原子状态转换只允许一个并发执行进入 `AUTH_PROBING`。完整有效快照会清除阻断状态，并在此前告警确实送达时创建一次恢复逻辑事件；只有明确的 401、403、登录页或认证重定向才会对新代数重新阻断。超时、5xx 或结构错误分别进入第 9.2、9.3 节的策略，不要求再次更换 Cookie。

Cookie 只能通过 Cloudflare 控制台的加密 Secret 输入框，或 `wrangler secret put` 的交互式标准输入写入；不得把值放在命令参数、配置文件或脚本中。Secret 只保存原始值，不含 `auth=` 名称。写入和使用时拒绝分号、逗号、空白、控制字符、额外 Cookie 对以及超过 4 KiB 的值，且不打印其内容。

Cloudflare Secrets 保存：

- OPENCODE_AUTH_COOKIE
- OPENCODE_WORKSPACE_ID
- PUSHPLUS_TOKEN
- PUSHPLUS_TOPIC
- PUSHPLUS_CALLBACK_SECRET

这些值不得出现在仓库、D1、命令历史、测试夹具、错误对象或应用日志中。

OpenCode Cookie 的内部最长轮换周期为 90 天；成员退出、权限人员变更或疑似泄露时立即轮换。疑似泄露时先关闭采集，在 OpenCode 上游退出或撤销旧会话。旧 Cookie 的拒绝验证由账号持有人在 Worker 之外以不记录凭据的人工受控方式完成；生产 Worker 在开关关闭时仍保持零次认证请求。若无法验证撤销，生产采集保持关闭。

## 7. 通知规则

### 7.1 首次启动

首次取得完整有效快照后，创建一个“监控已启动”逻辑事件，内容包含三档完整状态。首次快照作为基线，不补发历史阈值通知。

### 7.2 阈值通知

- 阈值为 50%、75%、90%、100%。
- 只有从阈值下方跨到阈值或上方时才触发。
- 若一次从 49% 跳到 92%，只发送该窗口当前达到的最高阈值 90%，不连续发送 50%、75%、90% 三条消息。
- 上述跳跃会把 50%、75%、90% 都标记为本周期已消费，但只有最高的 90% 进入消息；本周期内不得随后补发较低阈值。
- 多个窗口在同一次检查中触发时合并为一条消息。
- 同一窗口、同一周期、同一阈值只创建一个逻辑提醒事件；PushPlus 响应丢失时可能出现的物理副本遵循第 9.4 节的有界至少一次语义。
- 当窗口出现可信的周期变化，且百分比已经降到某阈值以下时，才重新启用该阈值，避免滚动窗口轻微下降后反复提醒。

### 7.3 周期变化

如果上游未来提供稳定的周期 ID，则直接使用周期 ID 变化判定新周期。没有周期 ID 时，周期变化需要同时满足：

- 百分比相对上一有效快照下降；并且
- 新的重置时间晚于上一重置时间；并且
- 当前抓取时间已经到达上一重置时间，允许最多 5 分钟时钟误差。

上一重置时间尚未到达时，即使百分比下降或重置时间滑动，也不能开启新周期。无法确认周期变化时保留原阈值状态并标记异常，不能直接清空所有通知记录。确认新周期后，只有当前百分比低于某阈值时才重新启用该阈值。

### 7.4 每日汇总

- 每天北京时间 09:07 发送。
- 每个北京时间自然日最多创建并完成一个汇总逻辑事件；物理副本遵循第 9.4 节。
- 内容包含三档百分比、重置时间、数据更新时间和是否有未恢复故障。
- 正常汇总只能使用本次执行取得的完整有效快照；采集失败时不把旧数据伪装成当前数据，也不标记当天汇总已发送。
- 若当天稍后首次采集恢复成功且汇总仍未发送，则补发一条标为“延迟汇总”的消息；跨到下一北京时间自然日后不补发前一天的汇总。
- 每日汇总 outbox 事件的 `not_after` 是当天北京时间 24:00；到期事件原子转为 `expired`，后续重试不得发送。

## 8. 消息格式

阈值消息示例：

> ⚠️ OpenCode Go 用量提醒<br>
> 5 小时额度：92%<br>
> 预计重置：今天 16:42<br>
> 每周额度：41%<br>
> 每月额度：18%<br>
> 更新时间：14:30

故障消息只说明故障类型和需要的人工动作，不包含原始响应、Cookie、工作区 ID 或错误堆栈。

## 9. 故障处理

### 9.1 认证失效

- 立即停止解析和更新配额。
- 只创建一次“登录失效，请更新 OpenCode 会话”逻辑事件。
- 同一凭据代数的后续任务不访问 OpenCode，也不重复推送。
- 更新 Cookie 并递增凭据代数后只允许一个并发执行进入探测状态；明确认证失败才重新阻断，临时或格式故障转入各自策略。

### 9.2 OpenCode 临时故障

- 单次执行最多重试两次，并使用短暂指数退避。
- 连续三个半小时周期失败后创建一个上游不可用逻辑事件。
- 保留最后一次有效快照，但明确标为过期，不将其作为新数据广播。
- 恢复后创建一个恢复逻辑事件。

### 9.3 页面或数据结构变化

- 任一关键字段缺失或格式不符时失败关闭。
- 不把缺失值转换为 0%。
- 每个结构故障 episode 只创建一个“采集格式变化，需要更新适配器”逻辑事件。

认证、临时上游和结构变化分别维护故障 episode。告警和恢复都使用 episode 级唯一键；只有对应告警已经最终送达时才发送恢复，否则直接关闭 episode，避免成员先看到“恢复”却从未看到故障。旧观察不能覆盖较新的故障或恢复状态。

### 9.4 PushPlus 故障

- 发送事件及不可变消息载荷先以唯一 ID 写入 D1，再由带租约的 outbox 执行者发送。
- 状态机为 `pending → sending → accepted/waiting_callback → succeeded`，明确失败可进入 `retryable`，超过次数进入 `dead`，超过时效进入 `expired`。
- PushPlus 同步接受请求后，把消息流水号写入当前尝试；专用回调以事件 ID 定位事件，使用常量时间比较校验覆盖“事件 ID + 截止时间”的 HMAC 签名，再校验时效、请求大小、事件类型、已知状态和流水号后更新最终结果。未知或非法回调返回 404，不改变状态。
- 初次发送和重试合计最多三次。日报在北京时间跨日后过期；阈值消息在对应配额重置或创建 24 小时后取较早者过期。
- 已知流水号处于等待回调时不得立即重发。若响应在 PushPlus 接受后丢失且回调也未到达，后续有限重试仍可能产生重复，因此系统提供的是“有界至少一次”而不是“绝对不重复”；每条消息包含稳定事件 ID 和数据时间，最多产生与三次尝试上限相对应的副本。
- 一旦任一尝试收到最终成功回调，事件和全部成员触发项原子标记成功，永不重发。

阈值触发项的状态为 `reserved → delivered | abandoned`。创建 outbox 事件时原子进入 `reserved`；最终成功进入 `delivered`；事件变为 `dead` 或 `expired` 时进入 `abandoned`，但在当前配额周期仍保持已消费，不另建替代事件，避免无限刷屏。下一可信周期才重新启用；账号持有人可从 D1 和脱敏日志发现并人工处理 abandoned 事件。

### 9.5 D1 故障

- 无法可靠读取去重状态时失败关闭，不发送阈值或汇总消息。
- 仅记录经过脱敏的 Cloudflare 错误日志，避免每次调度都向成员刷屏。

PushPlus 自身完全不可用时不能通过 PushPlus 报警，D1 完全不可用时也不能可靠创建报警事件；这是本方案的已知旁路限制。账号持有人需要启用并查看 Cloudflare 侧的运行失败通知或脱敏日志，不能把群内“没有消息”当作系统健康证明。

## 10. 安全与隐私

- OpenCode auth Cookie 等同于控制台密码；只有账号持有人可写入，生产部署和 Secret 管理权限也必须限制到最少人员并启用多因素认证。
- PushPlus Token 也是发送凭据，泄露后必须单独轮换。
- 代码只允许向预设的 OpenCode 与 PushPlus 精确 HTTPS origin 和固定路径发送请求；OpenCode Cookie 绝不附加到 PushPlus 请求。
- 预览环境和 CI 不绑定生产 Secrets；任何修改出站目标、Secret 绑定或回调校验的部署都需要人工复核，并保留 Cloudflare 侧的 Secret 写入与部署审计记录。
- 日志仅包含事件 ID、状态码、耗时和脱敏错误分类。
- 不记录响应正文，不记录请求 Cookie 头，不记录完整 PushPlus 请求。
- 通知内容会经过 PushPlus 和微信，且 PushPlus 当前可能保留消息约 30 天，因此只发送低敏感聚合数据。
- 提交前和 CI 中运行密钥扫描，并在测试中检查日志与夹具不存在疑似 Cookie 或 Token。
- 成员必须知道聚合用量变化仍可能间接暴露团队的活跃时间。

## 11. 测试设计

### 11.1 单元测试

- 正常三窗口响应的解析。
- 登录页、认证重定向、字段缺失和格式变化。
- 0%、100%、非法百分比和非法重置时间。
- 49% 到 76% 只触发 75%。
- 49% 到 92% 只触发 90%。
- 相同快照不重复通知。
- 多窗口同时跨阈值时合并消息。
- 周期可信变化后重新启用阈值。
- 上一重置时间尚未到达时，百分比下降或重置时间滑动均不重新启用阈值。
- 北京时间日期边界和每日汇总去重。
- 当天采集恢复后的延迟汇总，以及跨日不补发旧汇总。
- 每个入口都先执行阈值转换；09:00 为 49%、09:07 为 76%、09:30 为 77% 时只产生一次 75% 提醒。
- 49% 跳到 92% 时较低阈值同时被消费，本周期不再补发。

### 11.2 集成测试

- 使用模拟 OpenCode 响应和模拟 PushPlus 服务，不接触真实账户。
- 验证两次上游重试、三周期故障告警和恢复通知。
- 验证 PushPlus 异步接受、最终失败和后续重试。
- 并发两个首次执行和两个重试执行，验证 outbox 原子抢占使每次尝试最多一个执行者调用 PushPlus。
- 验证多窗口同时跨阈值时只创建一个广播事件，成功后全部成员触发项均完成。
- 验证旧观察晚完成不会回退快照、连续失败或恢复状态，每日任务失败不计入三个半小时周期。
- 验证故障 episode 的告警/恢复去重和顺序，包括 PushPlus 间歇失败。
- 验证 Cookie 中的分隔符、空白、控制字符、额外 Cookie 对和超长值被拒绝；相似域名、用户信息 URL、非标准端口、错误路径和认证重定向均不会收到 Cookie。
- 验证同一被阻断凭据代数产生零次后续 OpenCode 请求，新代数只产生一次恢复探测。
- 在请求前、外部接受后响应丢失、流水号落库后和成功回调后分别注入崩溃，验证租约、三次上限、有界重复和成功后不重发。
- 验证阈值事件三次失败或过期后触发项变为 `abandoned`，当前周期不再创建替代事件，新周期才重新启用。
- 验证伪造、超大、未知事件和错误流水号的 PushPlus 回调不改变状态。
- 验证日报重试跨过北京时间午夜后转为过期，不发送昨日汇总。
- 验证许可记录缺失、过期、撤销或不匹配，以及紧急开关关闭时，OpenCode 认证请求数均为零。
- 验证错误日志不含 Cookie、Token、邮箱或原始页面。

### 11.3 部署验收

1. 账号持有人和全部 2–5 位成员收到测试消息。
2. 首次真实快照与控制台三档数据一致。
3. 连续运行 24 小时没有无原因重复消息，并完成全部并发与崩溃注入测试。
4. 模拟 49% 到 76%、76% 到 92% 和周期重置均符合规则。
5. 模拟认证失效时只创建一个告警逻辑事件；PushPlus HTTP 尝试不超过三次，物理副本数按第 9.4 节单独核对。
6. 更新 Cookie 和凭据代数后只有一个并发执行进入 `AUTH_PROBING`；明确认证失败才重新阻断，成功后自动恢复并只创建一个恢复逻辑事件。
7. 汇总的逻辑调度时间为北京时间 09:07，每天只创建一个汇总逻辑事件；实际到达允许 Cloudflare 平台调度延迟，物理副本按第 9.4 节验收。
8. 凭据只存在于 Cloudflare Secret 绑定中，不出现在明文配置、D1、日志、构建产物、CI 输出、仓库或测试夹具中。
9. 生产账号启用多因素认证和最小权限，预览/CI 不绑定生产 Secrets，许可到期或紧急停用测试产生零次认证请求。

## 12. 初始部署与日常运维

初始部署需要：

1. 创建 Cloudflare Worker 和 D1 数据库。
2. 创建 PushPlus 私有普通群组并完成发送方实名认证。
3. 让成员通过受限二维码订阅并完成一次测试通知。
4. 在模拟模式完成全部规则测试。
5. 取得符合第 3 节范围的 OpenCode 书面许可，配置许可记录 ID 和到期时间。
6. 账号持有人登录一次 OpenCode，并通过安全方式写入五项 Cloudflare Secrets；设置初始凭据代数。
7. 配置并验证 PushPlus 回调密钥、消息测试、Cloudflare 旁路运行通知或日志检查流程。
8. 启用生产采集开关，验证首个完整快照。

日常运维只需要处理认证失效、成员变更、上游格式变化和密钥轮换。GitHub 密码永远不进入该系统。

## 13. 官方 API 迁移

官方 Go 用量 API 上线后：

1. 新增官方 API 适配器并使用官方认证方式。
2. 用相同的统一快照契约运行现有测试。
3. 双读比较控制台适配器和官方 API 一段时间。
4. 数据一致后切换到官方 API。
5. 删除控制台 Cookie Secret 和控制台适配器。

规则引擎、D1 表结构、Cron 和 PushPlus 通知层保持不变。
