# PushPlus 用量仪表盘重设计

## 目标

把当前由普通文字和 Unicode 方块拼接的用量消息改成移动端可扫读的仪表盘，同时继续满足以下约束：

- 消息正文不加载图片、字体、脚本或其他外部资源；
- `/go` 的 5 小时、每周、每月额度信息全部保留；
- `/usage` 的请求数、Token 汇总及分类、费用、模型排行和 24 小时明细全部保留；
- 自动广播时间、手动触发、幂等、outbox 重试、采集和历史 SVG 消息兼容行为不变；
- 样式失效时仍退化为顺序正确、数值完整的普通表格。

本设计取代 `2026-08-08-pushplus-inline-chart-design.md` 中“Unicode 方块图表”的新消息展示方式；旧文档继续作为历史决策记录，历史消息路由不受影响。

## 已确认的视觉方案

采用用户确认的“A 仪表盘最终组合”：顶部使用精简版的三个额度进度条，底部使用完整版的 24 小时精确数值。

消息从上到下分为六个区域。

### 1. 标题与观察时间

标题继续区分“整点用量”和“手动用量”。正文首行显示简短状态标题和北京时间观察时刻，不增加图片或图标资源。

### 2. 额度状态

5 小时、每周、每月各占一行。每行包含：

- 额度名称；
- 浅灰轨道和单色蓝色已用进度；
- 右对齐的已用百分比；
- 对应的完整重置时间，作为弱化的次要文字。

进度宽度按 `usedPercent` 直接映射到 0% 至 100%。百分比和重置时间始终以文字存在，不能只依赖颜色表达。

### 3. 汇总指标

使用三列表格展示最近 24 小时的请求数、Token 总量和费用。Token 分类不塞进卡片标题，而是在趋势图下方使用 2×2 表格展示输入、输出、推理、缓存四项精确汇总。

所有 Token 数量继续使用中文千分位；费用继续按现有口径显示四位小数。聚合被截断时，请求数、Token、费用和模型排行继续使用“至少”措辞。

### 4. 24 小时趋势柱图

趋势图固定包含 24 根竖向蓝色柱，顺序与现有北京时间小时桶一致，当前小时允许是部分小时。每小时柱高基于输入、输出、推理、缓存四类 Token 之和计算：

- 24 小时最大值对应 88 像素；
- 零值柱高度为 0；
- 非零值按 `round(该小时总量 / 最大值 × 88)` 计算，并设置 3 像素的纯视觉最小高度；
- 柱图下只放少量时间刻度，完整小时和数值由下方明细表承担。

视觉最小高度不会改变精确数值，也不会参与任何汇总。全零时保留空轨道和时间轴，不伪造用量。

### 5. 每小时精确数值

柱图下方固定展示全部 24 小时。正常数据采用两列、每列 12 行的紧凑表格，左列为前 12 个连续小时，右列为后 12 个连续小时；每一项包含：

- 北京时间小时标签；
- 与主柱图使用同一最大值归一化的迷你横条；
- 未缩写的精确 Token 整数，使用中文千分位。

区域标题已经标明单位为 Token，因此每一项不重复输出 `Token`，避免噪声。数字右对齐并禁止换行；数字较长时优先缩短迷你横条，不能截断或改成近似值。只要任一格式化数值超过 10 个字符，就确定性切换为单列 24 行，避免在 320 像素宽度下溢出。

### 6. 模型排行与元信息

模型排行由当前的一整句文字改成按行排列的表格，继续展示前 5 个模型及“其他”，每行包含模型名、Token 数量和占比。动态模型名必须经过 HTML 转义；展示名最多保留 64 个 Unicode 码点，超出部分使用省略号收尾，内部聚合键和数值不变。

观察时间、当前小时为部分小时的提示、截断提示和事件编号放在正文底部，使用弱化文字。事件编号仍完整保留，方便排障。

## HTML 与兼容策略

PushPlus 继续使用 `template: "html"`。官方消息接口明确支持 HTML 文本，普通消息内容上限为 2 万字：

- https://www.pushplus.plus/doc/guide/api.html
- https://pushplus.plus/doc/help/limit.html

生产正文以嵌套 `<table>`、`<tr>` 和 `<td>` 为核心布局，不使用 `flex`、`grid`、定位、SVG、Canvas、JavaScript 或远程资源。样式只使用内联属性，并限制为：

- 宽度、高度、内外边距；
- 字号、字重、颜色、对齐；
- 边框和纯色 `background-color`；
- `border-radius` 仅作渐进增强，去掉后布局仍正确。

重要纯色单元格同时写 `bgcolor` 和内联 `background-color` 作为兼容兜底。不使用渐变、背景图片或 `<style>` 标签。所有区域以 100% 宽度表格为基础，最窄按 320 像素详情页检查，不产生横向滚动。

渲染后的正文设置 18,000 字符安全预算，为 PushPlus 包装和后续小幅文案增长留出余量。规则测试使用 64 码点模型展示名和最大安全整数夹具验证预算。若富样式版本仍超过预算，则确定性改用兼容版表格：保留三个额度、全部汇总、24 小时精确数值、模型排行和元信息，只移除主柱图、迷你横条及装饰性边框；不得截断数值或删除数据。兼容版仍超过预算才视为渲染错误。

## 代码边界

- `src/rules.ts`：新增仪表盘 HTML 渲染辅助函数，替换当前 `renderInlineUsageChart` 和纯 `<br>` 明细拼接；消息入口和标题规则保持不变。
- `src/usage-domain.ts`：不改变聚合数据结构；现有 24 个小时桶和四类 Token 已足够渲染。
- `src/app.ts`、`src/repository.ts`、`src/pushplus.ts`：不改变广播、持久化和发送流程。
- `test/rules.test.ts`：以结构与数据语义断言替换 Unicode 外观断言。
- `README.md`：把新广播说明更新为纯 HTML 仪表盘；历史 SVG 兼容说明继续保留。

不重新引入 Browser Run、PushPlus 开放接口、图片上传、对象存储或新的 Cloudflare binding。

## 降级与安全

- 24 小时明细不可用时：继续显示三个额度进度条；明细区域替换为现有原因文案，不生成空的汇总卡、柱图或模型表。
- 合法零用量时：请求、Token、费用均显示 0，24 根柱为空，24 小时精确表全部显示 0。
- 聚合截断时：保留现有“至少”和“仅含已采集记录”提示。
- 无模型记录时：模型区域显示“暂无模型记录”。
- 所有动态文本继续经过 HTML 转义；百分比、时间、Token、费用和柱高只由已验证的内部数值生成。
- 样式被过滤时：表格文字顺序、百分比、重置时间和全部精确数值仍可阅读。

## 精简测试

只增加直接覆盖新渲染行为的测试：

1. 三个额度行同时包含标签、百分比、进度宽度和各自重置时间；
2. 主柱图固定生成 24 根柱，峰值、极小非零值和全零高度正确；
3. 精确表固定生成 24 个北京时间标签和 24 个未缩写数值，顺序无重复、无缺失；
4. 请求数、Token 分类、费用和模型排行仍使用现有统计口径；
5. 明细不可用、截断、无模型和 HTML 转义继续正确；
6. 正文不存在 `<img>`、外部 URL、SVG、Canvas、脚本或 Unicode 方块条；
7. 64 码点模型展示名和最大安全整数夹具覆盖两列转单列及 18,000 字符兼容版降级；
8. 现有定时、手动触发、outbox、回调和历史 SVG 路由回归测试继续通过。

## 上线与验收

合并后部署 Worker，只手动触发一次测试广播。验收同时检查 PushPlus 详情页和微信打开页：

- 三个额度进度条、百分比和重置时间完整；
- 三个汇总指标、24 根柱、四类 Token 汇总、24 小时精确数值和模型排行完整；
- 手机宽度无横向滚动，数字不截断；
- 正文没有图片和外部资源请求；
- 本次事件只创建一次、只投递一次且状态成功。

通过后继续按既定北京时间 09:00 至 23:00 整点规则运行，不额外发送消息。
