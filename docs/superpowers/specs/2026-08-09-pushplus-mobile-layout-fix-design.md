# PushPlus 仪表盘移动端布局修复设计

## 背景

生产烟测确认，现有纯 HTML 仪表盘没有在手机竖屏和系统字体放大时保持可读：

- 每项额度把名称、重置时间、进度条和百分比放在同一行的三个自动布局单元格中。文字的最小宽度随字体放大而增长，空内容的进度条单元格会先被压缩，内部 `width="100%"` 只能占据已经塌缩后的宽度。
- 24 小时精确值默认使用两列，每个半列内部再横向分配给小时、迷你条和禁止换行的数字。手机竖屏下每个数字只能得到约整屏 20% 的宽度，字体放大后会挤压迷你条并与相邻项目碰撞。
- 当前单双列切换只依据格式化数字是否超过 10 个字符，不能代表终端宽度、PushPlus 包装内边距或用户字体缩放比例。

根因是自动表格布局中的横向列竞争，不是额度百分比或 Token 数据错误。修复必须改变文档结构，不能依靠减小字号、固定像素宽度或媒体查询。

## 目标

1. 在 320–430 像素手机竖屏和常见字体放大场景中，三个额度进度条保持清晰可见。
2. 24 个小时的完整 Token 数值不互相挤压、不截断、不缩写，并按北京时间顺序显示。
3. 按用户选择的方案 B，富版精确值保留每小时迷你条。
4. 不依赖 `<style>`、媒体查询、脚本、图片、SVG、Canvas、外部字体或外部资源。
5. 保持 18,000 字符正文安全预算；降级不能删除 24 小时精确值。
6. 不改变采集、聚合、定时、手动触发、幂等、outbox、PushPlus 发送、回调或历史 SVG 路由。

## 非目标

- 不重新设计颜色、文案、主趋势图或模型排行。
- 不引入按设备、User-Agent 或屏幕宽度服务端分支。
- 不通过缩小字体掩盖拥挤问题。
- 不修改已发送的历史消息。

## 选定布局

### 额度区域

每项额度改为一个移动优先的两行结构：

1. 元信息行只有两个直接单元格：左侧显示额度名称及完整重置时间，右侧显示已用百分比。
2. 进度条行只有一个直接单元格，通过 `colspan="2"` 占满元信息行的两列。
3. 进度轨道内部继续使用固定 100% 宽度的两格表格表示填充和剩余比例；轨道与文字不再处于同一横向布局层。
4. 0% 不生成蓝色填充格，100% 不生成剩余格，继续避免伪填充和伪空隙。
5. 额度名称、重置时间和百分比保持原文；只有百分比可以禁止换行，进度条本身不依赖文字占位。

稳定结构标记：

- `data-quota="rolling|weekly|monthly"`：每项额度的独立表格；
- `data-quota-meta`：名称、重置时间和百分比所在行；
- `data-quota-bar-row`：全宽进度条所在行；
- 既有 `data-quota-progress`、`data-quota-remaining`、`data-quota-percent` 和 `data-quota-reset` 保留。

### 24 小时精确值区域

富版和兼容版都固定使用单列 24 项，不再根据数字长度切换双列：

1. 顺序严格等于聚合器提供的 24 个北京时间桶，不交错显示。
2. 每个小时使用独立项目表格，并以 `data-hour-value="HH"` 标识。
3. 第一行显示小时和完整 Token 数值；小时保持不换行，数值右对齐但不再使用 `nowrap`。
4. 极端大字体或超长整数允许只在自己的数值单元格内换行，不能侵入其他小时项目。
5. 富版第二行通过 `colspan="2"` 放置全宽迷你条，迷你条不与小时或数字竞争宽度。
6. 兼容版省略迷你条，但保持相同的单列顺序和完整数值。
7. 区域标题继续显示“24 小时精确值（Token）”，每个数值不重复单位。

稳定结构标记：

- `data-hour-layout="single"`：所有数据规模均固定为单列；
- `data-hour-row="HH"`：每个小时的直接外层行；
- `data-mini-bar-row="HH"`：富版迷你条直接外层行；
- 既有 `data-mini-bar="HH"` 保留。

### 其他区域

主趋势图、三个汇总指标、四类 Token 汇总、模型排行和页脚保持原有信息与顺序。本次只消除已经由生产烟测证实的两处横向竞争，不扩大为整份消息重设计。

## 富版、兼容版与正文预算

- 富版保留主趋势图和 24 个全宽迷你条。
- 若富版超过 18,000 字符，兼容版继续移除主趋势图和迷你条。
- 兼容版仍须保留三个额度、汇总、四类 Token、24 个单列精确值、模型排行、截断说明、观察时间和事件号。
- 若兼容版仍超过预算，沿用现有 `RangeError`，由上层降级为文字版；不能静默删除数值。
- 实现时应减少无语义的重复标记，确保典型生产数据仍可发送富版。

## 测试设计

测试以文档结构而非 CSS 字符串作为主要验收标准：

1. 先写失败测试，证明当前额度名称、进度条和百分比仍处于同一直接行。
2. 断言每项额度的元信息行不含进度轨道，进度条行只有一个直接单元格并 `colspan="2"`。
3. 覆盖 0%、50%、100%，确保比例、背景色和空段语义保持正确。
4. 先写失败测试，证明普通长度数据当前仍生成 12 行双列交错结构。
5. 断言富版与兼容版均生成 24 个直接小时项目，顺序为字面量 `00` 至 `23` 或对应真实跨日桶顺序，每个直接行只有一个小时项目。
6. 断言富版每个小时的迷你条在独立的 `colspan="2"` 行中，精确数字单元格不含 `nowrap`。
7. 覆盖零用量、跨日窗口、最大安全整数、截断数据、长模型名、HTML 转义和 18,000 字符降级。
8. 更新应用层仅与旧双列结构绑定的正文断言，不削弱事件状态、幂等、采集次数或投递次数断言。
9. 完整执行类型检查、项目测试、授权流程测试和 Wrangler 部署预检。

## 发布与验收

1. 通过中文 PR 合并，不直接修改生产分支。
2. 合并前不得部署或发送真实广播。
3. 合并后从最新 `master` 完成一次生产部署。
4. 只手动触发一次广播，核对 D1 中任务、事件、尝试和 PushPlus 回调均成功且尝试次数为 1。
5. 用户在微信手机竖屏中检查三个额度条和 24 小时精确值；不得为了观察外观重复发送。
