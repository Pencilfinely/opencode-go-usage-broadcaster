# OpenCode Go 整点广播与手动触发设计

## 目标

将现有按阈值、启动和每日汇总触发的通知，改为固定时段的整点用量广播：北京时间每天 09:00 至 23:00 每小时发送一条，00:00 至 08:59 不自动发送。同时提供一个安全、可重复使用的手动触发方式，手动触发不受静默时段限制。

## 自动广播规则

- Cloudflare Cron 使用 `0 1-15 * * *`，对应北京时间每天 09:00 至 23:00 整点。
- Worker 内再按 `Asia/Shanghai` 校验当前时间，仅允许 09:00 至 23:00 的整点任务创建广播，避免配置偏差导致静默时段发送。
- 每次任务抓取最新 OpenCode Go 用量，并发送一条包含滚动、每周和每月用量的汇总消息。
- 整点广播使用 `broadcast:scheduled:<北京时间日期>:<小时>` 作为稳定逻辑键。同一小时即使 Cron 重复投递，也只会创建一条消息。
- 消息最晚有效到下一个北京时间整点。发送失败的旧用量不会在后续小时补发。
- 停止创建旧的启动通知、阈值通知和 09:07 每日汇总，避免整点广播之外出现额外的正常用量消息。
- 采集失败时不发送过期或虚构用量；现有故障与恢复记录继续保留，但只能由 09:00 至 23:00 的定时任务产生，因此夜间仍保持静默。

## 手动触发

- Worker 提供精确路径 `POST /admin/manual-trigger`，不接受查询参数，也不提供公开 GET 链接。
- 请求使用 `Authorization: Bearer <MANUAL_TRIGGER_SECRET>` 鉴权。密钥至少包含 32 个随机字节，仅保存为 Cloudflare Worker Secret 和 GitHub Actions Secret，不写入源码、普通变量、URL 或日志。
- 请求必须携带 `Idempotency-Key`。服务端对该值做哈希，并使用 `broadcast:manual:<哈希>` 作为任务和消息逻辑键；同一个键不会重复发送，不同键可以再次手动发送。
- 手动触发同步等待抓取、入队和首次投递结束后返回成功，不通过后台悬空任务掩盖失败。
- 手动触发绕过自动广播的静默时段，但继续复用现有 D1 租约、任务幂等、用量采集和 PushPlus 投递链路，不另写一套发送实现。
- GitHub 增加名为“手动发送 OpenCode Go 用量”的 `workflow_dispatch` 工作流。用户在 GitHub Actions 页面点击运行即可；工作流以 GitHub 运行编号作为幂等键，并从仓库 Secret 读取鉴权密钥。

## 投递与防重复

- PushPlus 接口明确返回接受成功并提供消息编号后，即将该次投递记为成功。
- PushPlus 回调继续保留以兼容已经生成的回调地址，但不再因回调缺失而自动重发已被接口接受的消息。
- 该取舍优先避免群内重复消息；若 PushPlus 接受后最终渠道投递失败，不自动重发，由用户按需使用手动触发。
- 上线前通过一次数据迁移将仍处于活动状态的旧启动、阈值和每日汇总事件标记为过期，避免部署后补发旧消息。已成功或已终结的历史记录保留。

## 数据与兼容性

- 继续使用现有 `job_runs`、`outbox_events.logical_key`、确定性事件编号和快照租约，不新增状态表。
- 为降低生产数据库变更风险，整点与手动用量汇总继续复用现有内部 `regular` 任务类别和 `daily` 消息类别，具体语义由 `broadcast:scheduled:` 与 `broadcast:manual:` 逻辑键区分。
- `RuntimeState.startupCreated` 和 `lastDailyCreatedDate` 保持向后兼容读取，但新逻辑不再依赖它们。
- 手动触发不会占用或取消下一次整点广播；二者使用不同逻辑键。

## 安全与错误响应

- 手动入口只允许 POST；路径、方法或鉴权不符合要求时不泄露内部状态或密钥内容。
- Bearer 密钥采用固定长度摘要的常量时间比较。
- `Idempotency-Key` 仅接受长度受限的安全字符，数据库中只保存其摘要，不保存原值。
- 上游采集或投递失败时，HTTP 响应仅返回通用错误，不回显 OpenCode 会话、PushPlus 凭据或上游响应正文。

## 精简验证范围

- 验证北京时间 08:59 不发送，09:00、10:00 和 23:00 发送，次日 00:00 不发送。
- 验证同一整点任务重复执行不会重复创建或投递消息。
- 验证每次正常整点任务都会创建当前用量汇总，而不是等待阈值变化。
- 验证手动入口的路径、方法、Bearer 鉴权和幂等键；验证手动触发可在静默时段发送且不影响下一次整点广播。
- 验证 PushPlus 接口接受后不会因为回调缺失而重发。
- 运行现有类型检查和测试套件，确保真实 OpenCode 会话采集与 D1 并发控制不回归。

## 上线步骤

1. 配置新的 Worker Secret `MANUAL_TRIGGER_SECRET`，并将同一值保存为 GitHub Actions Secret。
2. 应用旧活动消息清理迁移。
3. 部署 Worker 和新的 Cron 配置。
4. 在静默时段确认不会自动发送，并执行一次 GitHub 手动触发验证。
5. 确认 D1 中手动任务成功、PushPlus 接口接受消息且下一整点任务仍能独立执行。
