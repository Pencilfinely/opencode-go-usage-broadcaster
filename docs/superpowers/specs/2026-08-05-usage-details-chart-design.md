# OpenCode `/usage` 明细与图表广播设计

## 目标

在现有 OpenCode Go 整点广播和手动广播中，保留 `/go` 页面的 5 小时、每周、每月三项额度，同时增加 `/usage` 页面最近 24 小时的具体使用情况。用户在微信中点开 PushPlus 通知后，可以直接看到 Token 汇总、各模型排行和按小时分层图表，不新增独立仪表盘。

## 已确认的产品决策

- 图表放在 PushPlus 消息详情页，不建设独立网页仪表盘。
- 统计范围为最近 24 个北京时间小时桶，包含当前未结束小时。
- 明细采用 24 小时汇总和模型用量排行，不展示最近若干条逐请求记录。
- 图表按小时展示 Token，并分为输入、输出、推理、缓存四层。
- 自动广播仍为北京时间每天 09:00 至 23:00 整点；手动广播仍可随时触发。
- 以快速实现为主，只增加与新采集、聚合、图表和消息渲染直接相关的验证。

## 方案选择

采用“复用 OpenCode 会话并回放 `/usage` 请求”的方案。授权工具在一次可见浏览器登录中识别 `/go` 和 `/usage` 两类请求，Worker 继续使用已捕获的 OpenCode 会话 Cookie，无需保存 GitHub 密码，也无需在每次广播时启动浏览器。

不采用以下方案：

- 官方 Usage 导出接口：该接口只接受服务账户密钥，普通用户会话不能调用，不能保证当前 Go 账户具备所需组织权限。
- 定时浏览器截图：需要长期运行浏览器或购买浏览器执行服务，页面结构变化也会直接破坏采集，不符合当前纯 Worker 架构。

## 已确认的 OpenCode 上游契约

OpenCode 当前官方源码中，`/workspace/<工作区>/usage` 的明细区通过名为 `usage.list` 的只读服务函数获取数据。服务端固定每页 50 条，按 `timeCreated` 倒序，参数只有工作区标识和从零开始的页号。

每条记录包含稳定的 `id`、`timeCreated`、`model`、`provider`、`inputTokens`、`outputTokens`、可空的 `reasoningTokens`、`cacheReadTokens`、`cacheWrite5mTokens`、`cacheWrite1hTokens`、以微美分计价的 `cost`、可选 `keyID`、可选 `sessionID` 和套餐来源。现有页面把空的推理和缓存字段按零展示，并采用以下计算口径：

- 输入小计 = `inputTokens + cacheReadTokens + cacheWrite5mTokens + cacheWrite1hTokens`；
- 输出小计 = `outputTokens + reasoningTokens`；
- Token 总量 = 输入小计 + 输出小计；
- 美元费用 = `cost / 100000000`。

本功能严格复用上述口径，不自行解释或重新定价。官方页面的现有图表按月展示费用；本功能根据用户已确认的需求，基于同一批明细记录另外生成最近 24 小时 Token 图表。

## 授权包与采集流程

### 授权包版本

将会话授权包升级为版本 2，包含：

- 一个会话 Cookie；
- `/go` 用量请求描述；
- `usage.list` 第零页请求描述；
- 可选的 `usage.list` 分页请求模板及页号替换位置；
- 两个请求所属的同一工作区标识；
- 创建时间和经过白名单筛选的必要请求头、方法及请求体模板。

Worker 在过渡期继续接受版本 1 授权包。版本 1 只能发送现有三项额度，并在消息中注明“24 小时明细尚未授权”；完成一次新版授权后即使用完整内容。

### 授权工具

授权工具继续打开一次临时可见浏览器。用户完成 GitHub 登录并进入工作区后，工具按顺序访问 `/go` 和 `/usage`。工具只把响应能够通过现有三项额度解析器或本设计规定的 `usage.list` 记录解析器验证的请求纳入版本 2 授权包。浏览器关闭后删除临时配置目录。

授权工具先捕获 `usage.list` 第零页请求；当页面存在下一页时，自动触发一次下一页并捕获页号为 1 的请求。两个请求必须具有相同的协议、主机、路径、方法、查询参数集合、请求头集合和除页号外完全相同的序列化参数。工具只有在两份响应均为合法的 50 条倒序用量记录，且能够唯一定位页号参数时，才生成分页模板。

若授权时全部历史记录不足 50 条，版本 2 授权包可以标记为“单页模式”。后续广播一旦取得满 50 条而又没有安全分页模板，`/usage` 明细必须降级为不可用并提示重新授权，不得把前 50 条冒充完整的最近 24 小时数据。

捕获规则遵循最小权限：

- 仅接受 `https://opencode.ai`；
- 禁止跨域重定向；
- 工作区标识必须与 `/go` 请求一致；
- `/go` 只允许无查询参数的 `GET /workspace/<工作区>/go`；
- `usage.list` 只允许授权工具实际捕获的同源只读服务函数路径、原始方法和原始非页号参数，运行时只可替换经过验证的非负整数页号；
- `usage.list` 请求体最大 16 KiB，页号之外的字节在运行时必须与授权模板一致；
- 只保留 `Accept` 和实际需要时的 `Content-Type`，拒绝 `Authorization`、`Origin`、`Referer`、`X-*` 及其他自定义头，Cookie 单独保存；
- 查询参数必须与模板完全一致，禁止运行时追加参数；
- 日志、错误和命令输出不得打印 Cookie、请求体中的凭据或完整授权包。

### Worker 回放

每次整点任务或手动任务复用同一 Cookie，分别回放 `/go` 和 `usage.list` 请求。两者均使用 10 秒单请求超时、禁止重定向和 512 KiB 单响应上限。解析器先校验内容类型和数据结构，再转换为内部模型；不得根据无法识别的页面文本猜测数值。

`usage.list` 从第零页开始读取，每页固定 50 条；第零页验证成功后，其余页面每批最多并行读取 4 页。每条记录先按稳定 `id` 去重，再按时间范围筛选；读取到第一条早于 24 小时起点的记录或不足 50 条的一页即停止。单次广播最多读取 40 页，即 2000 条记录，并设置 25 秒的整段明细采集期限，为 `/go`、PushPlus 和其他 Worker 子请求保留余量。达到页数或时间上限仍未越过 24 小时起点时，结果明确标记为截断，所有总数和排行使用“至少”措辞，图表注明“仅含已采集的最新记录”，不得展示为完整数据。

OpenCode 使用偏移分页，采集期间新产生的记录可能令相邻页重叠。稳定 `id` 去重可消除重复；采集开始后的新记录统一留到下一次广播，不为追求强一致性循环重试上游。

## `/usage` 内部数据模型

每条规范化用量记录包含：

- 稳定记录编号；
- 发生时间；
- 提供商、模型和套餐来源；
- 输入 Token；
- 输出 Token；
- 推理 Token；
- 缓存读取 Token；
- 5 分钟缓存写入 Token；
- 1 小时缓存写入 Token；
- 以微美分计价的费用。

记录编号、发生时间、模型、提供商、输入 Token、输出 Token 和费用必须存在且通过类型、范围校验，否则整页无效。根据 OpenCode 当前页面的既有口径，空的推理和三个缓存字段规范化为零。所有 Token 和费用必须是非负安全整数。

缓存层等于缓存读取、5 分钟缓存写入和 1 小时缓存写入之和。Token 总量严格等于输入、输出、推理和缓存四类之和，不与输入重复计算。费用严格使用上游微美分字段汇总，系统不依据模型单价自行估算。

## 24 小时聚合

聚合以北京时间为准。对任意执行时间，取当前北京时间小时及其之前 23 个小时，共 24 个连续小时桶；当前桶允许是部分小时。超出范围的记录不进入消息和图表。

聚合结果包含：

- 24 小时请求总数；
- Token 总量和输入、输出、推理、缓存分类值；
- 费用总额；
- 每小时四类 Token 数值；
- 按 Token 总量降序排列的模型排行。

消息最多直接列出前 5 个模型，字段为模型名、Token 数量和占比；其余模型合并为“其他”。Token 数量相同时按模型名稳定排序。没有记录是合法的零用量状态，不视为采集失败。

## 消息结构

PushPlus 继续使用 HTML 模板。消息详情按以下顺序渲染：

1. `/go` 的 5 小时、每周、每月额度；
2. 最近 24 小时请求数和 Token 总量；
3. 输入、输出、推理、缓存 Token 明细；
4. 上游费用总额；
5. 前 5 个模型及“其他”的用量排行；
6. 24 小时 Token 分层图表；
7. 数据观察时间、当前小时为部分小时的说明和广播事件编号。

数值使用紧凑格式，同时保留足以区分数量级的精度。所有来自上游的模型名和文本在插入 HTML 前必须转义。即使图表无法加载，文字汇总和模型排行仍能完整表达本次用量。

## 图表生成与访问

Worker 自行生成静态 SVG 图表，不把聚合数据发送给第三方图表服务。图表使用 24 根堆叠柱，依次表示输入、输出、推理和缓存 Token；横轴使用北京时间小时，纵轴根据最大桶自动缩放，并提供固定中文图例和数据观察时间。

新增普通配置 `PUBLIC_BASE_URL`，值为 Worker 的公开 HTTPS 根地址；新增 Worker Secret `USAGE_CHART_SIGNING_SECRET`。每张图表的地址形式为：

`GET /charts/usage/<快照编号>.svg?sig=<签名>`

签名使用 HMAC-SHA-256 覆盖快照编号和固定用途字符串，并进行常量时间比较。图表接口只允许 `GET`，只接受一个 `sig` 查询参数，不接受 Cookie 或授权包。SVG 只由内部数值和固定标签生成，响应使用 `image/svg+xml; charset=utf-8`、`Content-Security-Policy: default-src 'none'; sandbox`、`X-Content-Type-Options: nosniff` 和 `Cache-Control: public, max-age=3600`。

由于 PushPlus 和微信必须能从公网读取图片，持有完整签名链接的人可以查看该张聚合图表。链接不包含 Cookie、API 密钥、提示词、逐请求记录或成员身份信息；签名防止枚举其他快照。

外链 SVG 的真实微信验证是发布门槛，不是上线后的可选检查。若预览 Worker 的手动测试无法显示 SVG，本设计不视为验收通过，必须先重新选择并确认图片渲染方案；本次规格不预先承诺尚未选型的 PNG 路径，也不得临时改用会泄露用量数据的第三方图表服务。

## 数据库存储与保留

新增 `usage_chart_snapshots` 表，至少包含：

- 快照编号；
- 数据观察时间；
- 24 个小时桶和图表所需分类值的 JSON；
- 创建时间。

创建广播事件时，在同一受租约保护的数据库提交中保存图表快照和待发送消息，避免消息引用尚未存在的图表。只保存聚合值，不保存 Cookie、请求头、提示词、逐请求正文或完整上游响应。

图表快照保留 30 天。任务执行时每次最多删除 200 条更早的快照，清理失败不阻断本次用量广播。超过保留期且数据库记录已删除后，图表接口返回 `404`；客户端此前最多可按一小时缓存继续显示。

30 天只定义图表快照在 Worker 数据库中的保留期。现有 `outbox_events` 中的 HTML 消息正文以及 PushPlus 自身的消息保留沿用当前行为，不在本次需求中新增清理策略；因此本设计不声称 30 天后删除所有文字汇总。

## 失败与降级

- `/go` 成功、`/usage` 失败：仍发送三项额度，在明细区域注明暂不可用，不引用图表。
- `/go` 成功、`/usage` 返回合法空数据：发送零用量汇总和零值图表。
- `/go` 失败：沿用现有采集失败处理，不发送可能过期的额度或明细。
- 图表快照写入失败：本次消息不得引用不存在的图片；仍可降级发送文字明细。
- 图表读取或渲染失败：返回通用错误或 `404`，不回显数据库内容和内部异常。
- 会话失效或页面协议改变：记录脱敏故障状态，提示重新运行授权工具，不尝试保存或自动填写 GitHub 密码。
- 手动广播和整点广播复用同一采集、聚合、快照和消息链路，继续使用各自现有的幂等键，互不占用水位。

## 安全边界

- OpenCode 会话授权包和图表签名密钥只保存为 Cloudflare Worker Secret。
- 图表签名密钥与手动触发密钥分离，不复用现有密钥。
- 日志只记录阶段、错误类别、工作区哈希和事件编号，不记录上游正文或用量明细。
- 模型名、时间标签和错误文本均经过对应上下文的 HTML 或 XML 转义。
- 上游响应仍受大小、超时、内容类型和结构校验限制，防止异常页面占用过多资源。
- 图表只暴露账户级聚合 Token 数，不暴露成员、请求内容和逐条记录。

## 精简验证范围

自动验证只覆盖新增风险：

- 版本 2 授权包校验，以及版本 1 的降级兼容；
- `/usage` 成功、空数据、未授权、鉴权失败和结构变化；
- 北京时间 24 小时边界、当前部分小时、模型排序和“其他”合并；
- OpenCode 既有 Token 计算口径、空推理/缓存字段和微美分费用处理；
- 50 条分页、稳定编号去重、单页授权升级提示和 2000 条截断标识；
- HTML/XML 转义、消息降级和图表地址生成；
- 图表签名正确、篡改拒绝、未知快照 `404`；
- 整点与手动广播各验证一条端到端主路径；
- 运行现有测试套件，确认三项额度、时间窗口、防重和手动发送不回归。

发布前通过预览 Worker 执行一次真实微信端验证：手动发送一条消息，确认点开后文字、模型排行和 SVG 图表均可见。该检查通过后才允许部署到现有生产 Worker。

## 上线顺序

1. 应用 `usage_chart_snapshots` 数据库迁移。
2. 配置 `PUBLIC_BASE_URL`，生成并保存 `USAGE_CHART_SIGNING_SECRET`。
3. 将兼容版本 1 和版本 2 授权包的新 Worker 发布为预览版本。
4. 运行新版授权工具，登录一次并捕获 `/go` 与 `usage.list` 请求，上传版本 2 授权包。
5. 在预览版本手动发送一条消息，验证真实 `/usage` 数据、文字明细和微信 SVG 图表。
6. 预览验证通过后部署到现有生产 Worker。
7. 确认下一次整点任务仍按原时间规则发送，并检查降级与日志中没有敏感数据。

## 验收标准

- 每条正常整点或手动消息保留三项 Go 额度，并显示最近 24 小时 Token 汇总和模型排行。
- 图表包含 24 个北京时间小时桶和输入、输出、推理、缓存四类 Token。
- 用户在微信中点开 PushPlus 通知后能够看到图表；聊天列表无需直接展开图片。
- `/usage` 故障不会阻止三项额度消息，且不会显示虚构或过期明细。
- 系统不保存 GitHub 密码，不把用量数据发送给第三方图表服务。
- 旧版授权包可以安全降级，新版授权完成后无需每次重新登录。
- 自动广播时间、手动触发、防重和现有 PushPlus 投递行为保持不变。
